# 2026-11-10

## Step 31 — Fixed the `users.test.ts` timeout properly, not just observed it

2026-11-08's journal noted two `users.test.ts` timeouts under full-suite load as "CPU contention, not a
regression" and left it there. Asked to actually fix it rather than wave it off, and to prove the fix
holds by running the full suite repeatedly, not once.

### Root cause, not just a symptom

`passwordService.hashPassword` used argon2id's library defaults (64 MiB memory cost, time cost 3) -
correct for production, but genuinely expensive on every single call, test or not. `users.test.ts`'s
`mustChangePassword`/reset-password tests hash and verify more than once per test; under the combined
weight of the full suite's other 383 tests running first, real argon2 work pushed a couple of them past
the default 5s test timeout. Not flaky in the sense of nondeterministic logic - just real, deliberately
slow cryptographic work with no slack left once something else was also using the CPU.

### Fix

`passwordService.ts` now picks cost parameters based on `process.env.NODE_ENV`: production (and dev)
keep argon2id's real-world defaults untouched; `=== "test"` specifically (verified directly - Vitest
sets this automatically, no config needed) gets `memoryCost: 1024, timeCost: 2, parallelism: 1` - same
algorithm, same code path, just cheap enough that hashing stops being the bottleneck. `verifyPassword`
needed no change - argon2's hash output encodes its own cost parameters, so verification reads them
back off the hash string regardless of which side generated it.

Deliberately gated on `"test"`, not `!== "production"` - a staging environment should still hash at
real cost; only the test runner's own process gets the cheap path.

### Verification

- `users.test.ts` alone: 34.8s -> 2.5s for the same 59 tests (14x).
- Full suite, run three times in a row as asked, no changes in between:
  - Run 1: 442/442, 107.67s
  - Run 2: 442/442, 110.48s
  - Run 3: 442/442, 107.64s
  - (For comparison, the pre-fix full run was 399.21s with 2 failures.)
- `npm run lint`, `npm run typecheck`: clean.
