# 2026-10-06

## Step 21 — Retire the generic 9-stage lifecycle module (ADR 0010)

Slice A's backend and web UI are both merged and working end to end, which is the condition
ADR 0007 point 8 set for removing the original Module 1: `Product`, `ProductVersion`,
`StageDefinition`, `ProductStageHistory`, `Approval`, `ProductStageAssignment(+History)`,
`StageProgressNote`, and everything built on them, API and web both. One PR, branch
`chore/retire-generic-lifecycle`.

### What came out

- **API**: 8 repositories, 10 services, 3 controllers, 2 route files, 9 test files, the
  `stageDefinitionSeedData` seed file. `userService.ts` too, once it turned out its only caller
  (`authService.register`) was also being removed - see below.
- **Web**: 3 pages, 10 components(+tests), 4 lib modules(+tests), `api/products.ts`, the
  assignee-view test file, plus a misleadingly-named `MovedBackDetail.test.tsx` that turned out
  to test the old `ProductDetailPage`'s stage-history rendering, not a standalone component -
  found only by actually reading its imports, not by its filename.
- **Schema**: the 8 tables (migration drops them, FKs first), `ProductStatus` and
  `AssignmentAction` enums, and the 9 now-dead relation fields on `User`.
- **`packages/shared-types`**: every type/const tied to the old response shapes, rebuilt.
- **`UserRole`**: `MANAGER`/`ENGINEER` dropped from the enum entirely - not renamed into
  `MANAGEMENT`/`ENGINEERING`, since they don't mean the same thing and this is dev data with no
  real users forcing a migration path (ADR 0010, point 2). Final set is seven values.

### A decision that wasn't in the original plan: self-registration

`authService.ts` hardcoded `REGISTRATION_ROLE = "ENGINEER"` for public self-registration. With
`ENGINEER` gone, every remaining role means something real - `FINANCE` gains a PO-upload
permission in the Slice B plan - so there's no longer a role that's safe to hand to an anonymous
caller. Removed the endpoint entirely (`POST /auth/register`, its controller/route/service
function, `RegisterRequest` from shared-types, the register-specific describe block in
`auth.test.ts`) rather than pick a new default. Accounts come from the seed only for now; an
admin "create user" endpoint is future work. Recorded as ADR 0010 point 4 rather than decided
silently, since it wasn't in the original instruction.

`userService.createUser` (email validation, password policy, the race-safe create) had no other
caller once `register` was gone, so it went too, along with the now-dead
`passwordService.assertPasswordPolicy` and `userRepository.create`. `apps/api/tests/auth.test.ts`
lost its whole `POST /auth/register` describe block and switched its `registerUser()` test helper
to creating users directly via Prisma (`prisma.user.create` + `hashPassword`), since that's the
only way left to get a test user into the database.

### The migration: a deliberately non-default order

A plain `prisma migrate diff` would narrow `user_role` before touching the old tables. Did it the
other way around instead, per instruction:

1. Drop the old module's foreign keys, then its tables, then its two enums - nothing left in the
   database can reference a `MANAGER`/`ENGINEER` user afterward.
2. `DELETE FROM users WHERE role IN ('MANAGER', 'ENGINEER')`. Every SOP table's FK to `users` is
   `onDelete: Restrict` (ADR 0006, point 9), so if either seeded user (`owner@`, `engineer@`) had
   created any SOP data, this step would fail with a foreign-key violation instead of silently
   deleting rows a real decision was needed about. It didn't fail - neither had any.
3. Only then swap `user_role` to the final 7-value enum (rename/recreate/cast/drop, the same
   procedure as every earlier enum change in this project).

`prisma migrate dev --create-only` refused to run non-interactively in this environment ("the
environment is non-interactive, which is not supported") even piping `yes` into it - it checks
whether stdin is a TTY, not whether input is available. Worked around it: generated the raw diff
separately with `prisma migrate diff --from-config-datasource --to-schema ... --script` for
reference (to get the exact FK constraint names), hand-wrote the migration folder and SQL file
directly in the ordering above, then applied it with `prisma migrate deploy` (which doesn't
prompt) instead of `migrate dev`. Confirmed in sync afterward by re-running the same `migrate
diff` and getting "This is an empty migration."

Sequences (`prj_code_seq` etc.) are untouched - not reset. Whoever runs this migration for real
should follow it with `prisma migrate reset` on the dev database if they want codes to restart
at `PRJ-000001`.

### Everything else that had to be found, not guessed

- `apps/api/tests/globalSetup.ts` seeded `stageDefinitionSeedData` on every test run; now it just
  truncates. `apps/web/src/test/fixtures.ts`'s `ALL_SESSIONS` dropped `managerSession`/
  `engineerSession` - most SOP test files filter that array dynamically by role and needed no
  further change, but two had the legacy roles spelled out as literals
  (`sopPermissions.test.ts`'s `ALL_ROLES`, one `it.each` in `TechPackDetailPage.test.tsx`) and
  would have broken at runtime (an `undefined` session) rather than at compile time.
- `App.tsx`'s `/` now renders `ProjectListPage` directly (no redirect route) - the simplest of
  the options, since there's nothing left for it to redirect from. `AppHeader` lost the
  "Products"/"Delayed" nav links.
- `apps/web/src/auth/auth.test.tsx` is a generic auth-flow test, not an old-module one, but all
  of its data-loading stubs pointed at `/products`/`/stages`/`/delayed` - rewritten against
  `/projects` and friends, including the "ends the session on a 401 from an action, not just a
  load" test, which now fires a `POST /projects` instead of the old "mark assignment ready".
- `e2e/smoke.spec.ts` asserted a "Products" heading right after login; now asserts "Projects"
  (the new default) and clicks through to "Proto Requests" instead of the old "Projects" nav
  check.
- README's API/Frontend sections described the old module almost exclusively and had never
  caught up with Slice A's actual endpoints - this was a real rewrite, not a deletion pass:
  added proper endpoint tables for Projects/Tech Packs/Proto Requests/Attachments with their
  role gates, and the real SOP route table.
- ADRs 0003/0004/0005 (workflow-as-data, stage-level access control, approval records) marked
  "Superseded by ADR 0010" rather than deleted, so the reasoning stays readable as history.
