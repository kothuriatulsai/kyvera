### Part 3 — Deferred blob URL revoke

`api/attachments.ts`'s download helper was calling `URL.revokeObjectURL()` immediately after
`link.click()`. The browser reads the blob asynchronously *after* the click, so an immediate
revoke can race an in-progress download. Changed to `setTimeout(() => URL.revokeObjectURL(url), 1000)`.

### Things that went wrong (both found and fixed before finishing)

- **The new `e2e` workspace's `"test"` script collided with the root's own `npm run test
  --workspaces --if-present`.** A plain `npm test` at the repo root started trying to run
  Playwright too - with no servers up, since that command doesn't know about the CI step's
  server-lifecycle choreography. Caught by actually running `npm run test` at the root after
  adding the workspace, not just assuming it would be fine. Fixed by renaming the script to
  `test:e2e`, which the generic `--workspaces` sweep doesn't match, and updating CI's own
  invocation to match.
- **GitHub Actions' bash steps run under `set -e` by default.** The Playwright step's own
  "capture the exit code, kill both servers, then exit with that code" pattern would have
  skipped straight past the kill on a Playwright failure, since `set -e` aborts the script at
  the first non-zero command. Bracketed just that one command in `set +e` / `set -e` so cleanup
  always runs regardless of whether the smoke test passes.
